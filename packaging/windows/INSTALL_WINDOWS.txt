OmniCore Host (OCH) 0.8.0 — Windows Installation and Driver Notes
(Chinese version: INSTALL_WINDOWS.zh-CN.txt)

Scope
  Windows 10 / Windows 11, native x64. The current release does not support ARM64 or 32-bit Windows.
  USB data device: OmniCoreSDR, VID 1A86 / PID 5537.
  Driver: libusbK 3.1.0.0. The installer is fully offline and includes the user-mode DLL, kernel driver,
  installation tools, and licenses.
  The release contains the OCH programs, C/C++ interface, examples, user documentation, and the USB2
  measurement appendix; it does not include the PS SDK, board firmware, or the full test project.
  The installer never builds or flashes the Zynq, FPGA, or CH32.
  The SoapySDR plugin (used by GNU Radio / SDR++ and others) is not included. The plugin has to be built
  with the same compiler as SoapySDR (radioconda and PothosSDR both use MSVC), using the MSVC import
  libraries shipped with this installer; see docs\soapy.md for the steps. The plugin has not yet been
  verified on hardware under Windows.

First installation
  1. Close any other software that accesses the SDR and run OmniCoreHost-0.8.0-win64-setup.exe.
  2. Accept the normal Windows administrator UAC prompt. Keep the "Install/check libusbK" option.
  3. After installation, open a new terminal and run:
       och find
       och info
       och help
  Terminal output is organized in titles and groups, with color and live progress; it switches to plain
  text automatically when redirected. Use --no-color or set NO_COLOR if you do not want color. Scripts
  should use --json, whose result structure stays compatible.
  The software installation also completes without an SDR connected. Afterwards, connect the USB data
  port (USB 3.x recommended) and run:
       och-driver install

Driver helper
  och-driver check        Only queries the driver of the target SDR; does not modify the system.
  och-driver install      Installs libusbK automatically; does not replace an existing libusbK.
  och-driver extract DIR  Only unpacks for inspection; does not create/trust certificates or install
                          the driver. DIR must not exist; the extracted INF is deliberately left unsigned.

Installation behavior
  The driver helper only selects non-composite USB devices with VID 1A86 / PID 5537; it does not modify
  WCH-Link, serial ports, keyboards, USB hubs, or any other VID/PID. With several identical SDRs, the same
  driver applies to all of them.
  Using libwdi's normal flow, the helper generates an INF and a one-time signed catalog for this device,
  adds the signing certificate generated for this device to the Windows certificate store, and then lets
  Windows install it.
  The kernel libusbK.sys is the unmodified official file; its fixed SHA256 and Windows Authenticode
  signature are checked before installation.
  Test signing is never enabled, and Secure Boot, signature enforcement, and Memory Integrity are never
  turned off. If system security policy rejects the driver, the helper reports a failure; it never
  lowers system security settings automatically.

Errors and logs
  Driver installation log: C:\ProgramData\OmniCoreHost-driver{GUID}\install.log
  Windows installation details: C:\Windows\INF\setupapi.dev.log
  setup.exe supports /LOG="full log path"; when the software installs but the driver fails, the
  installer exit code is 104.
  Driver helper exit codes: 0 success/already usable; 2 device not connected; 3 libusbK needed; 4 error;
  5 UAC cancelled.
  Exit code 2 (device not connected) does not fail the software installation; just run
  och-driver install later.

Updating and uninstalling
  Run a newer setup.exe directly to update the software. First stop streaming and exit programs that
  hold the DLL.
  Uninstalling only removes the OmniCore Host software and the PATH entry for its install directory. It
  does not remove the shared libusbK driver, the driver certificate, or the system DriverStore package,
  to avoid affecting other devices that use the same driver.
  Keep your capture files in your own working directory; the installer never creates or deletes them.

Dependencies and sources
  licenses\ contains the licenses for libusbK, libwdi, and the GNU/MinGW runtime, with source URLs and
  download SHA256 values.
  licenses\sources\ keeps the corresponding upstream source archives; licenses\driver-build\ keeps the
  helper source code and build scripts.
  This software and installer are not yet signed with a publisher code-signing certificate; Windows may
  show an unknown publisher prompt.
  The kernel driver's signature and the application code signing above are two different things.

Verification scope
  Verified: building the driver helper, enumerating the target device, idempotent skip when libusbK is
  already present, offline extraction, exact INF matching, kernel file hash/signature, and the installer
  contents. The existing libusbK on the test computer was left unchanged.
  The first-time driver installation has not been run on a clean Windows virtual or physical machine;
  that still needs separate installation acceptance.
  If a clean system lacks a trusted root needed for signature verification, the offline signature check
  may refuse to install; handle it through normal Windows updates and organizational policy. This
  installer never downloads or imports external CA roots to bypass that verification.
