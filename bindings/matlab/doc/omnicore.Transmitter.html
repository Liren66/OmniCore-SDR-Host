omnicore.Transmitter System object

Transmit frames to an OmniCoreSDR; also usable in a Simulink MATLAB System block

Creation

tx = omnicore.Transmitter

tx = omnicore.Transmitter(Name, Value)

Usage

underflow = tx(x)

x
N × numel(ChannelMapping) frame: single / double complex scaled to ±1, int16, or int8 (IQBits 8). Frames join into one unbroken burst; the call returns as soon as x is queued.
underflow
True if the device ran out of samples since the last call: frames must arrive at no less than the sample rate.

release(tx) sends the queued samples and then stops.

Properties

PropertyDefaultDescription
Device[]Same as Receiver
SerialNumber''Same as Receiver
ChannelMapping11, 2, or [1 2]; sets the device's TxChannels
SampleRateNaNHz; NaN keeps the device's current value
CenterFrequencyNaNHz, tunable. Changing the TX LO briefly pauses transmission (the core discards queued samples)
GainNaNdB, 0 – 89.75, tunable, scalar or per channel
Latency0.1Seconds of zeros sent before the first frame: how far the device runs behind the writes, i.e. how long MATLAB can stall without underflowing
BufferBytesNaNHost ring buffer; NaN means 64 MiB
Timeout1Seconds to wait for buffer space

Examples

tx = omnicore.Transmitter('CenterFrequency', 2.45e9, 'Gain', 20, 'SampleRate', 30.72e6);
x = single(0.5 * exp(1j*2*pi*(0:30719).'/30.72));     % 1 ms, 1 MHz tone
for k = 1:5000
    if tx(x), disp('underflow'), end
end
release(tx);

With only a Transmitter and no Receiver, the loop is not paced by the device: tx(x) returns immediately until the buffer is full, and then waits for the device to take data.

Tips

  • For occasional underflows, increase Latency and avoid plotting or printing inside the loop.
  • The first time a Simulink model runs after starting MATLAB, compilation causes one longer pause and may report one underflow; later runs do not.
