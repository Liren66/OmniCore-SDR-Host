Errors and Warnings

omnicore:* identifiers, causes, and fixes

All error and warning identifiers start with omnicore:. Error messages include the reason given by OmniCore Host. Handle them by identifier:

try
    [x, meta] = read(rx, n);
catch err
    switch err.identifier
        case 'omnicore:TIMEOUT'
            x = [];                 % no data during this period
        otherwise
            rethrow(err);
    end
end

Errors

IdentifierMeaningFix
omnicore:InvalidArgumentWrong argument type, name, or range (checked before calling the device)Correct the argument as described in the message
omnicore:INVALIDOmniCore Host rejected the request, e.g. several devices are connected but no serial number was givenCorrect as described in the message
omnicore:BUSYThe device is open in another program; the same direction already has a stream; channels changed while streams exist; reopening a stream after one direction stopped in full duplexClose the other program; stop the existing stream; see the full-duplex start/stop rules
omnicore:NOT_FOUNDNo device found, or the given serial number does not existCheck the connection, driver, and udev rule; omnicore.findDevices
omnicore:TIMEOUTNo data or no progress within TimeoutCheck the timed start time; increase Timeout
omnicore:IOUSB transfer failedCheck the data cable, power, and USB port; reopen the device
omnicore:STOPPEDThe stream has been stopped (e.g. the device was closed during the call)Start the stream again
omnicore:UNSUPPORTEDThe firmware does not support this featureUpdate the firmware
omnicore:PROTOCOL, omnicore:BUFFER_SMALLDevice communication or internal buffer problemReopen the device; report the problem if it persists
omnicore:InvalidHandleThe device or stream behind the object has been closedCreate the object again
omnicore:InterruptedCtrl+C interrupted a long call (requires building with OCH_MATLAB_CTRL_C)The object is still usable
omnicore:LibraryNotFoundWindows: omnicore.dll or libusbK.dll missing next to the MEX fileUse the complete release package folder
omnicore:OutOfMemoryMATLAB ran out of memoryReduce the number of samples, or use int16 output
omnicore:InternalInternal errorReport the problem

Warnings

IdentifierMeaning
omnicore:GainLimitedRX gain exceeded the upper limit of the current band and was clamped to it
omnicore:TxClippedTransmit samples exceeded ±1 and were clipped
omnicore:TxLateThe start time of a timed burst had already passed
omnicore:TxUnderflowThe device ran out of samples while transmitting
omnicore:TxErrorThe device reported a TX error
omnicore:TxNotSentSome samples were never sent when stopping (less than one USB transfer without EndBurst)
omnicore:TimeInvalidatedChanging the sample rate invalidated a hardware time that had been set
omnicore:TransportUSB transfer errors occurred since the last call (merged into one warning)
omnicore:CloseFailedClosing the device or stream failed while deleting the object

Warnings you do not need can be turned off, e.g. warning('off', 'omnicore:TxClipped').

Installation problems

SymptomCause and fix
macOS: the MEX file "cannot be opened because the developer cannot be verified"Run xattr -dr com.apple.quarantine omnicore-matlab
Linux: Invalid MEX-file …GLIBCXX_3.4.xx not foundMATLAB loaded its own older libstdc++ first. The release package links the C++ runtime statically; when building yourself, use the release package's CMake settings (-DOCH_STATIC_LIBSTDCXX=ON)
omnicore.findDevices is emptyCheck the USB data cable; on Windows install the driver (och-driver install); on Linux install the udev rule; the command-line och find gives diagnostics
Windows build: Supported compiler not detectedMATLAB does not recognize the newer Visual Studio; install Visual Studio 2022 Build Tools or use a newer MATLAB
