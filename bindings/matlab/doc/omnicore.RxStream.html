omnicore.RxStream handle class

Continuous receive from an omnicore.Device

Creation

rx = rxStream(dev)

rx = rxStream(dev, Name, Value)

rx = omnicore.RxStream(dev, Name, Value)

Creates the stream object without starting to receive; after start, the device begins writing samples into the host ring buffer, and read takes them out.

Name-value arguments

'OutputDataType' 'single' (default) | 'double' | 'int16' | 'int8'
See Sample Formats and Scaling.
'BufferBytes' bytes, default 64 MiB
Host ring buffer. While MATLAB is not reading, samples wait here in the wire format (3 bytes per complex sample for 12-bit, 2 bytes for 8-bit): 64 MiB is about 0.36 s at dual-channel 30.72 MSPS.
'Timeout' seconds, default 1
How long read waits for each block of data; can also be changed later through rx.Timeout.

Properties

DeviceThe device it belongs to (read-only)
OutputDataType, BufferBytesSettings at creation (read-only)
TimeoutSeconds, 0 < Timeout ≤ 3600, can be changed
IsRunningWhether the stream is running (read-only)

Object functions

start(rx)

Starts receiving; the device keeps receiving between read calls. Errors if already running.

start(rx, 'StartTime', t)

Starts at hardware time t (seconds). The first read has to wait until t, so Timeout must be larger than the delay until t.

[x, meta] = read(rx, n)

Reads n samples per channel; meta is the same as for receive. Samples lost between two read calls (buffer overflow) are recorded in row 1 of meta.Gaps. If a block of data does not arrive within Timeout, what has been received is returned; if no samples at all were received, omnicore:TIMEOUT is raised.

stop(rx)

Stops; unread samples are discarded. You can start again afterwards to begin a new stream (in full duplex, see the start/stop rules).

delete(rx)

Stops and releases.

Examples

Continuous receive with drop counting 
dev = omnicore.Device('SampleRate', 15.36e6, 'RxChannels', 1);
rx = rxStream(dev);
start(rx);
lost = 0;
for k = 1:200
    [x, meta] = read(rx, 65536);
    lost = lost + sum(meta.Gaps(:, 2));
    % ... process x ...
end
stop(rx);
fprintf('%g samples lost\n', lost);
Change frequency while running 
start(rx);
x1 = read(rx, 1e5);
dev.RxFrequency = 2.46e9;          % the stream keeps running
[x2, meta] = read(rx, 1e5);         % meta.Reconfigured is true

Tips

  • Each device has only one RX stream: while the stream is running, receive and a second stream raise omnicore:BUSY.
  • Channels and IQBits require stop first; frequency and gain can be changed while running; changing the sample rate pauses the stream and then continues.
  • When processing is slower than real time, the buffer overflows: increase BufferBytes, do less processing per block, or capture everything at once with receive.
