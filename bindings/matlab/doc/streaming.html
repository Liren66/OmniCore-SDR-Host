流、全双工与丢样

接收和发射如何共用一台设备，丢样如何报告

每台设备一个 RX 流、一个 TX 流

方向占用这个流的操作
RXreceive（调用期间）、运行中的 RxStream、Receiver（第一次调用到 release）
TXtransmit（调用期间）、transmitRepeat（到 stopTransmit）、活动的 TxStream（第一次 write 到 stop）、Transmitter

同一方向同时有第二个操作时报 omnicore:BUSY。RX 和 TX 可以同时运行（全双工）。

全双工的启停规则

任何一个流停止之后，只有在两个方向都停止时才能开新流。也就是说，TX 正在发射时，RX 可以开始一次，但停了就不能再开；反过来也一样。违反时报 omnicore:BUSY（“stop both directions before reopening a stream”）。

原因是 core 要在两个方向都停下时才复位 USB 管道。实际做法：

  • 全双工测量用一个一直运行的 RxStream（或 Receiver）配一个 TxStream（或 Transmitter），而不是每次测量调用一次 receive。
  • 在运行的 RX 流里按硬件时间戳截取需要的部分，见示例 video_link 和 timed_burst_loopback。
  • 要换一种用法时，先停掉两个方向（stop、stopTransmit、release）。

一个循环里收发

dev = omnicore.Device('RxChannels', 1, 'TxChannels', 1, 'TxGain', 20);
rx = rxStream(dev); tx = txStream(dev);
start(rx);
write(tx, complex(zeros(0.1 * dev.SampleRate, 1, 'single')));   % 100 ms 余量
for k = 1:1000
    write(tx, make_block(k));          % 立即返回（缓冲有空间时）
    [y, meta] = read(rx, 122880);      % 等设备：循环按采样率运行
    process(y);
end
stop(tx); stop(rx);

read 等待设备的数据，所以循环自然按采样率运行；先写入的一段零让 TX 领先于循环，MATLAB 偶尔停顿时不会欠流。omnicore.Transmitter 的 Latency 属性做的是同一件事。

RX 丢样

设备把样点连续写入主机环形缓冲（默认 64 MiB）；MATLAB 两次读取之间缓冲满了才丢样。丢样会被精确报告：

  • meta.Overflow 为 true；
  • meta.Gaps 每行 [行号, 丢失数]：数据在该行之前缺了多少样点（由硬件时间戳算出）；两次 read 之间丢的样点记在第 1 行；
  • 丢失的样点不补零，数组只含实际收到的样点，时间戳 meta.TimeTicks 指向第一个样点。

避免丢样：加大 BufferBytes；减少每块的处理和绘图（drawnow limitrate、隔几块画一次）；高速率时用 receive 一次采完再处理。

TX 欠流

突发进行中设备没有样点可发时报 Underflow（status / Transmitter 的输出），这是射频上的中断。Starved 只表示主机队列暂时为空：定时突发等待开始时间时也会出现，此时无害。

运行中修改参数

参数运行中
频率、增益、增益模式、带宽可以，流不停；接收数据 meta.Reconfigured 为 true。改 TX 本振时 core 丢弃已排队的 TX 样点
采样率可以，流暂停后继续；硬件时间重新开始
通道、IQBits不可以，先停止所有流（omnicore:BUSY）
