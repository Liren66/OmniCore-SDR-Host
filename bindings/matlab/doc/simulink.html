Simulink

Real-time RX/TX in Simulink models

Adding blocks

  1. Drag a MATLAB System block from Simulink › User-Defined Functions in the Library Browser.
  2. Set the System object name to omnicore.Receiver or omnicore.Transmitter.
  3. Set the properties in the block dialog (the same as in MATLAB; see Receiver and Transmitter).

The blocks run in "Interpreted execution" mode; code generation is not supported. The Receiver has three outputs (frame, valid, overflow), and the Transmitter has one input (frame) and one output (underflow).

Timing

  • With SampleRate set, the Receiver sample time is SamplesPerFrame / SampleRate; with SampleRate NaN, it is inherited.
  • The simulation is paced by the Receiver waiting for each frame, i.e. it runs in real time; the model's stop time is the number of seconds it runs.
  • A model with only a Transmitter is not paced by the device and needs a Receiver or another way to set its pace.

Full duplex

Simulink initializes all blocks before the simulation starts, so a Receiver block and a Transmitter block with the same SerialNumber (e.g. both '') share one device and run RX and TX at the same time.

The example simulink_duplex_example.m builds and runs a full-duplex model (Receiver → gain → Transmitter) from a script; save_system('omnicore_duplex') saves it.

Known behavior

  • The first time a model runs after starting MATLAB, compilation causes one longer pause, and the Transmitter may report one underflow; later runs do not. You can increase Latency.
  • Simulink does not allow character parameters to be tunable, so GainMode can only be set before simulation; CenterFrequency and Gain can be changed during simulation.
  • R2024b shows "not recommended" notices for matlab.system.mixin.Propagates and SampleTime; they are kept to support R2018a.
