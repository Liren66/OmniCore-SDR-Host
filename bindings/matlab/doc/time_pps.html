Hardware Time and PPS

Schedule and timestamp RX/TX with the device's sample clock

Hardware time

The device has a 64-bit sample counter: 1 tick = 1 sample, and time (seconds) = ticks / SampleRate. Every block of received data carries the count of its first sample, and transmission can specify the count at which to start, so the timing between RX and TX is exact to the sample, independent of USB and MATLAB latency.

OperationTime
time(dev), timeTicks(dev)Read the current time
receive(..., 'StartTime', t), start(rx, 'StartTime', t)Start receiving at t
meta.Time, meta.TimeTicksTime of the first sample of each block of received data
transmit(..., 'StartTime', t), write(tx, x, 'StartTime', t)Start a burst at t
s.AckTime, s.AckTicksTime at which the device confirmed the end of a burst

When you need sample accuracy, compute in ticks (uint64) and divide by the sample rate at the end; a StartTime given in seconds is rounded to the nearest sample.

Timed RX/TX pattern

fs = dev.SampleRate;
t = round((time(dev) + 0.05) * fs);                     % 50 ms from now, rounded to a sample
write(tx, burst, 'StartTime', t / fs, 'EndBurst', true);
% in the running RX stream, use meta.TimeTicks to cut out the samples around [t, t + numel(burst))

The lead time must be long enough for the device to receive the data: typically 30–100 ms. If it is too short, the device reports Late. The example video_link uses this pattern to send frame by frame; timed_burst_loopback uses it to measure TX→RX latency.

PPS time alignment

TimeSourcePPS comes from
'none'No PPS
'external'External PPS input (GPS receiver, etc.)
'internal'PPS generated on the board from the reference clock
'sync'TRIG signal shared by several boards
dev.ClockSource = 'external';              % external 10 MHz (optional; makes the sample clock share the reference)
dev.TimeSource = 'external';
setTime(dev, 0, 'AtNextPPS', true);        % sample time is 0 at the next PPS edge
pause(1.5);
[tp, ticks] = lastPPS(dev)                 % 1 second, ±1 sample

After that, whole-second hardware times fall on PPS edges, and several devices (each connected to the same PPS and 10 MHz) are aligned simply by using the same StartTime.

Notes

  • PPS is asynchronous to the sample clock, so the latched value has ±1 sample jitter.
  • Changing SampleRate restarts the hardware time; if the time had been set, an omnicore:TimeInvalidated warning is given and you need to call setTime again.
  • The "time has been set" state persists after closing and reopening the device (status(dev).TimeValid).
